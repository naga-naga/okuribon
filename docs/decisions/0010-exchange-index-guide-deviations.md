# 0010 交換会一覧でビジュアルガイドから採らなかったもの

- 日付：2026-08-21（この記録に集めた日。各項目を決めたのは #94 / #131 / #132 / #159 の時点）
- 発端：#182（元は `docs/spec.md` 10.2「ガイドから採らなかったもの」）

## 決めたこと

交換会一覧（6.6、ガイドの `ログイン・招待・交換会一覧.dc.html`）について、
資料の描き方を以下の7点で採らない。

## 項目

### 交換会一覧の「終了した交換会（3）」

**決めたこと** — 畳む口を持たない

**なぜ** — 畳む先ができるのは結果公開が溜まってからで、それまでは押しても中身が無い。
参加数は多くても十数件を想定しており（10.）、終わったものも含めて全件並べて
困る数にならない。結果公開のカードは結果画面への導線を持っているので、
畳むと行き先ごと隠れる。フェーズや主催による絞り込みをいまは置かないのも、
同じ見積もりに乗っている（6.6）

**却下した代替案** — 資料は見出しの右端に、終了したものを畳む口を置く

### 交換会一覧の「交換会をつくる」の置き場所

**決めたこと** — 本文の見出しの右に置き、帯からは外す（6.6）

**なぜ** — 帯の中ではこの画面でいちばん小さい字になり、
主催をはじめる道がそこにしかないのに見つけにくい

**却下した代替案** — 資料は帯（共通ヘッダー）の中だけに置き、本文には出さない。
資料が本文に置かないのはカードの並びに別種のものが混ざるためだが、
見出しの右は並びの外なのでその理由には当たらない。
資料がその位置に置いていた「終了した交換会（3）」は採っていない（上の項目）

### 交換会一覧の「いま動いているのは2つ。」

**決めたこと** — 件数は置かない（6.6）。
資料が同じ一文の後半に書いている並び順の説明のほうは残す

**なぜ** — 動いているものはカードの強さの3段階で朱になるので、**朱のカードの枚数と
件数は一致する。** 参加数は多くても十数件を想定しており（10.）、目で数えられる
枚数しか並ばない画面で、同じものを文字でも数えることになる。並び順の説明を残すのは、
並びがどの軸で決まっているかはカードを見ても分からないため

**却下した代替案** — 資料は 04 の見出しの下に動いている件数を出す。
ただし並びの軸そのものは資料と違う（次の「交換会一覧の並び順の決め方」）

### 交換会一覧の並び順の決め方

**決めたこと** — 次の締切の近い順にする（6.6）

**なぜ** — フェーズで群に分けると、フェーズが変わった瞬間にカードが群をまたいで
大きく動く。締切なら1本の軸なので、時が進んでも位置が少しずつしか動かない。
資料の並びとは準備中の位置だけが食い違う。まだ何もできない交換会が上に来ることは
あるが、締切の欄が生成りに沈んでいるので、急かされているものと取り違えることはない

**却下した代替案** — 資料は「自分の操作を待っているもの」を上と書く
（希望提出 → 登録 → 実行待ち → 結果公開 → 準備中）

### 交換会一覧のカードの一文

**決めたこと** — `Exchanges::Todo` の見出し（「希望リストを整える」）だけを並べる

**なぜ** — 冊数まで書いた一文は同サービスの補足のほうにあり、交換会ページが出している。
一覧で決めるのは「どれを開くか」までなので、開いた先と同じ長さの文を並べる用がない

**却下した代替案** — 資料は「希望リストが3冊。取得枠2冊に対してもう少し増やせます」と
状態を説明する文を置く

### 交換会一覧の残り時間の単位

**決めたこと** — いちばん大きい単位ひとつだけにする（6.1 と同じ）

**なぜ** — この画面は複数の交換会の残りを縦に並べるので、
桁数が揃っているほうが多い少ないを見比べやすい

**却下した代替案** — 資料は「6日 3時間」「4時間 12分」と2つ併記する

### 交換会一覧の締切の欄の揃え

**決めたこと** — どれも左揃えで通す

**なぜ** — 揃えがフェーズで変わると、同じ交換会を数日おきに開いたときに
同じ数字が別の位置に出る。狭い画面ではこの欄がカードの下へ回り込み、
左揃えでしか収まらない

**却下した代替案** — 資料は朱の面のときだけ左揃え、それ以外は右揃えにする

## 影響する場所

- `app/views/exchanges/index.html.erb`
- `app/services/exchanges/todo.rb`
