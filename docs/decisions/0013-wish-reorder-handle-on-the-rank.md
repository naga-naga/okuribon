# 0013 希望リストの並べ替えの口を順位のハンドル1つに寄せる

- 日付：2026-08-21（この記録に集めた日。決めたのは #128 / #130 / #151 / #154 の時点）
- 発端：#183（元は `docs/spec.md` 6.2 に織り込まれていた経緯）

## 決めたこと

希望リストの行に置く並べ替えの口を1つにし、その口を行の順位そのものにする（6.2）。

- ↑↓ のボタンは置かない
- ⠿ は行から落とす
- ハンドル（＝順位）は外す口と同じ44px（広い画面は32px）にする
- ハンドルは読み上げに渡す

## なぜ

口を減らした先にあるのは題の幅にあたる。行に口が4つ（ハンドル・↑・↓・×）並ぶと、
広い画面の340pxのリストでは題に88pxしか残らず、6文字で切れる。狭い画面（375px）も
口が44pxになるぶん97pxで変わらない。どれを何位にするかを決める画面で題が読めないのでは、
順位を動かす前の話になる。口が1つ減ると、題に渡る幅は広い画面で172px、狭い画面で193pxまで
戻る（ハンドルが別にあった間は152pxと173px）。数字はいずれもブラウザで測ったもので、
幅の見積もりではない。

何を、なぜ落としたか。

- **↑↓** — 以前はハンドルと並べて置いていた。ドラッグはつまめる人にしか使えず、
  キーボードからも読み上げからも届かないので、どちらにも渡る道が別に要る、という理由だった。
  道が要ること自体は変わらないが、それをハンドル自身に持たせれば、口を2つ並べずに済む
- **⠿** — 右端に置いていた間は、外す口と隣り合っていた。44pxの的が4pxの隙間で並ぶので、
  並べ替えようとして希望から外す取り違えが起こりうる。外すほうは確認を挟まずその場で消えるので、
  間違えたときの損が大きい。順位へ移すと、押すものが行の両端に離れる
- **24pxのハンドル** — ↑↓ と並べていた間は24pxまで詰めていた。指で押す並べ替えの口が
  ここだけになるので、押せる大きさのほうを採る。順位は16pxの素の文字だったので、
  その差ぶん題を削ることになるが、押せるかどうかと引き換えにする幅ではない
- **読み上げから伏せたハンドル** — ドラッグ専用だった間は伏せていた。ボタンにして
  名前と操作の説明を持たせる
- **⠿ の形が言っていたこと** — ⠿ はその形だけでつまめることを言っていたが、数字にはそれが無い。
  朱はすでに順位に乗っているので（10.1）、合図を色で足す道も塞がっている。
  代わりに外す口と同じ輪郭を持たせて、押せるものであることを見せる

引き受けたものが1つある。**画面から見える並べ替えの口が1つ減る。** マウスは使えるが
つまむのが難しい人に、押せば動くボタンが残らない。キーボードには残るが、目で見つかる道ではない。
リストの上に操作を1行で書き、ハンドルからも同じ説明へ繋ぐことで補う（6.2）。

## 却下した代替案

- **⠿ と × のあいだを空ける／× を行の外へ出す** — 取り違えは減らせるが、
  いちばん遠くへ離せるのは順位のほうにあたる
- **ホバーで順位を ⠿ に変える** — 指にはホバーが無く、つまむ操作をいちばん使うのは
  狭い画面にあたる
- **順位を直接指定する（順位の欄をセレクトにするなど）** — 任意の位置へ一手で入るが、
  行の左端に十数個の入力口が縦に並ぶ。題の幅を取り戻すためにボタンを落とすのに、
  順位の欄が広がっては元も子もない。キーボードから端へ送る道は Home / End が持つ（6.2）
