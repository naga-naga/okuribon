# 0012 交換会トップを廃し、交換会ページへ統合する

- 日付：2026-08-21（この記録に集めた日。決めたのは #136 / #139 / #140 の時点）
- 発端：#183（元は `docs/spec.md` 6.1 に織り込まれていた経緯）

## 決めたこと

状態だけを見せる交換会トップを持たず、交換会の中を1枚に畳む（5. / 6.1）。
統合に伴って次を決めた。

- 導線は「あなたがすること」の直下に置き、独立した段を作らない（6.1）
- 「次にすること」の一文は `Exchanges::Todo` に一本化する（6.1 / 6.6）
- 交換会ページの URL は交換会そのもの（`/exchanges/:id`）とし、
  `/exchanges/:id/books` は読む経路として持たない（6.1）
- 旧 URL からの転送も置かない（6.1）
- 主催者管理画面への導線は交換会ページが持つ（6.1 / 6.8）

## なぜ

参加者がこのツールで時間を使うのは本を読み比べているときで、トップはそこへ
向かう途中の通過点にしかなっていなかった。同じ行き先を指す導線が主と副で
2つ並んでいたのも、トップの仕事が一覧への送り出しに寄っていたためにあたる。

統合前に何を持っていて、統合でそれがどうなったか。

- **導線の段** — 統合前は導線を1段として持っていた。その日の主な行き先だった
  本の一覧がページの下半分そのものになったので、段に残るのは操作だけになる。
  操作は「すること」の一部にあたるので、独立した段を立てる理由が消えた
- **フェーズだけで決まる一文** — 統合前は本の一覧の見出しの下に、フェーズだけを
  見て選ぶ一文を別の経路で組んでいた。統合すると同じページに2つの「次にすること」が
  縦に並ぶことになるうえ、片方は本人の状態を見ず、もう片方は見るので、
  言うことが食い違いうる
- **URL** — 統合前の `/exchanges/:id/books` は、統合後は交換会ページと同じものを指す。
  残すと1つの画面に2つの入口ができ、交換会一覧のカードやパンくずがどちらを指すのかを
  画面ごとに選ぶことになる
- **主催者管理画面への入口** — 統合前は交換会トップが唯一の入口だった。
  トップを廃してもこのページが同じ位置にあるので、経路は変わらない

## 却下した代替案

- **旧 URL からの転送を置く** — 一度は「既に配られたリンクのために転送する」と
  書いたが、配られたリンクは無い。統合を入れた時点でまだ一度もデプロイしておらず、
  `/exchanges/:id/books` を手元に持っている人がいなかった。守るものが無い転送を置くと、
  以後ずっと持ち回すことになる。同じ URL は本の登録を受ける POST の口としては残るので、
  消えたのは読む経路だけ

## 影響する場所

- `docs/spec.md` 5. / 6.1 / 6.2 / 6.8
- `app/views/exchanges/show.html.erb`（状態ヘッダーと本の一覧が同じ画面にある）
- `config/routes.rb`（`/exchanges/:id/books` は `resources :books, except: [:show, :index]`
  のぶんだけで、読む経路を持たない）
- ビジュアルガイドの採否は 0006（状態ヘッダー）と 0007（本の一覧）にある
