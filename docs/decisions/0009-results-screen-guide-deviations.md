# 0009 結果画面でビジュアルガイドから採らなかったもの

- 日付：2026-08-21（この記録に集めた日。各項目を決めたのは #32 / #33 / #35 / #91 の時点）
- 発端：#182（元は `docs/spec.md` 10.2「ガイドから採らなかったもの」）

## 決めたこと

結果画面（6.5、ガイドの `結果画面.dc.html`）について、
資料の描き方を以下の8点で採らない。

通知（7.）に触れる項目は、#43 が未実装だった時点の判断にあたる。
#43 は完了したので前提は変わっている。採否を見直すなら新しい記録を立てる。

## 項目

### 結果画面の「◯◯ さんにお礼」と「本の詳細を見る」

**決めたこと** — どちらも置かない。脇そのものを作らず、
ストアへの導線はギフトコードのすぐ下に置く

**なぜ** — 通知は 7. の担当なので（#43）、Discord への下書きは押した先がまだ無い。
詳細画面は持たない（6.3 / 0005）。残るのがストアだけになるので脇を作る用がなく、
コードを使う先がストアなので、離して置く理由もない

**却下した代替案** — 資料はこの2つとストアへの導線を右の脇にまとめる

### 結果画面の「◯◯ さんへ（第1希望）」

**決めたこと** — 渡った先の名前だけを出す。順位は出さない

**なぜ** — 受け取った人の希望リストの中身にあたり（8.）、1冊でも出せば
その人のリストの一部が漏れる。加えて、順位が低いと渡った事実より順位のほうが
目に残る。返却について「選ばれなかったことを本の評価として読ませない」と
書いているのと裏腹になる

**却下した代替案** — 資料は自分が出した本の行き先に、受け取った人の希望リストで
何番目だったかを添える

### 結果画面の全体の結果の「残り5冊を表示」

**決めたこと** — 全件並べる

**なぜ** — 理由は本の一覧のカードと同じで（0007）、数人から十数人の交換会なので（10.）、
畳んで隠すほどの数にならない。誰が誰の本を受け取ったかを見る表なので、
隠すと用を成さない

**却下した代替案** — 資料は表を7行で切って続きを畳む

### 結果画面の松葉の面に並ぶ全体の数

**決めたこと** — 成立と返却の数は下の全体の結果の見出しに置く。
松葉の面が言うのは受け取った冊数だけにする

**なぜ** — 数を数えるのは全体の結果の仕事で、上部にも持たせると
同じ数が1つの画面に2か所出る

**却下した代替案** — 資料は「7人 12冊のうち 10冊が成立」を見出しの右に置く

### 結果画面の「抽選順を見る」の位置

**決めたこと** — 表の下に `details` として畳む

**なぜ** — 開くと参加者の並びが出るので、見出しの右で開くと表を押し下げる。
開閉するものは、開く先の隣に置く

**却下した代替案** — 資料は全体の結果の見出しの右端に置く

### 結果画面のギフトコードのボタンの出し分け

**決めたこと** — コピーを最初から出す

**なぜ** — 伏せたままコピーできれば、そもそも開かずに済む。表示を挟ませると、
コピーしたいだけの人にも一度画面へ出させることになる

**却下した代替案** — 資料は伏せ字のときは「コードを表示」だけを出し、
開いてから「コピー」と「隠す」に差し替える

### 結果画面のあらすじ

**決めたこと** — 載せない

**なぜ** — 読み比べは本の一覧の仕事で、結果画面で読むのは
贈り主のおすすめポイントのほう

**却下した代替案** — 資料も載せず、6.5 も挙げていない。
資料と食い違う判断ではなく、載せない側で揃っている

### 受け取った本が0冊の結果画面

**決めたこと** — 松葉の面の見出しだけを差し替え、事情は下の面に書く

**参照できるもの** — 資料に対応する絵が無い。`結果画面.dc.html` は 01 / 02 / 03 とも
1冊以上受け取った状態で、`状態バリエーション.dc.html` の「D 自分が0冊」は
登録期間の交換会ページにあたる。参照できるものが無かったので、
採否ではなく補いにあたる
