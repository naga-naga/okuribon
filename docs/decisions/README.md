# 判断の記録

「いつ・何を・なぜ決めたか」を1件1ファイルで積む。規範は `docs/spec.md` が持ち、
ここには決めた経緯と却下した代替案を置く。守るべきことをここにだけ書かない。
記録を読まないと実装の可否が分からない状態になったら、その決まりは spec.md へ移す。

記録は書き換えない。決めた内容が変わったら新しい記録を足し、
古い記録の冒頭に新しい番号への参照を添える。いつ何を考えていたかが残ることに
この置き場の意味があるため。

## ファイル名

`NNNN-英小文字ケバブの要約.md`。番号は4桁の連番。コードやドキュメントから
`decisions/NNNN` の形で参照するため、振り直さない。

## 書式

```markdown
# NNNN 決めたことの要約（終止形）

- 日付：YYYY-MM-DD
- 発端：issue / PR の番号

## 決めたこと

## なぜ

## 却下した代替案

案ごとに、なぜ採らなかったかを書く。

## 影響する場所

この判断に乗っているコード・文書・skill。無ければ節ごと省く。
```

1決定1ファイルを基本とする。同じ画面のビジュアルガイドの採否のような
細かい同種の判断をどうまとめるかは #182 で決める。
