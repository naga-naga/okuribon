# 不変条件の確認

okuribon には、壊れると取り返しがつかない不変条件が4つある。ユーザーが気付くのは
たいてい手遅れになってからなので、差分に対して機械的に確認する。

まず対象の差分を取る。

```
git diff main...HEAD    # ブランチ全体
git diff                # 未コミットの変更
```

各項目は grep で当たりを付けてから、**該当箇所を実際に読んで**判断する。
grep が無反応だったことを根拠に「問題なし」と結論しない。差分が触ったファイルは目で追う。

## 1. ギフトコードの可視性

見えてよいのは2者のみ。その本を登録した本人（常時）と、マッチング成立後にその本を
受け取った人。**主催者に特権はない。**

```
rg -n 'gift_code' app/ --glob '!**/*_spec.rb'
```

確認すること。

- 取得経路が1つに限定され、権限判定がそこに集約されているか。
  モデル・ビュー・コントローラに判定が散っていたら、それ自体が問題
- 一覧系に混入していないか。index アクション、コレクションを回すビュー、カード用の
  パーシャル、JSON レスポンス、Turbo Stream の更新対象
- `select` や `pluck` で明示的に列を絞っている箇所に紛れ込んでいないか
- ログに出ていないか。`filter_parameter_logging` の対象になっているか
- 例外時のダンプやエラー画面に載らないか

ビューでは、伏せ字が既定で、明示的な操作で開く形になっているかも見る。

## 2. サーバー側のフェーズ検証

書き込み系の操作は、必ずサーバー側でフェーズを検証する。クライアントの時刻計算に依存しない。

```
rg -n 'def (create|update|destroy)' app/controllers/
```

確認すること。

- 追加・変更された書き込みアクションに、フェーズの検証が入っているか
- ビューでボタンを出し分けているだけで、サーバー側の検証が無い箇所はないか。
  URL を直接叩けば通ってしまう
- 検証が共通化された1か所を通っているか。アクションごとの手書きになっていないか
- 期間の境界。**開始時刻を含み、終了時刻を含まない。** 締切ちょうどはその期間の外
- 参加の辞退と参加者の除外は、登録期間の締切まで。希望提出期間に入ってから
  参加者が抜けると取得枠の計算が壊れる

## 3. 状態カラム・乱数シード・マッチングの一回性

```
rg -n 'status|state|phase' db/migrate/ app/models/
rg -n 'seed|rand|shuffle|sample' app/ db/ --glob '!**/*_spec.rb'
```

確認すること。

- **フェーズの状態カラムを増やしていないか。** フェーズは日時カラムから導出する
- 乱数シードが交換会の作成時に固定されているか。実行時に生成していないか。
  あとから変更できないようになっているか
- マッチングが一度だけ実行され、再実行できないか
- マッチングの実行が行ロックとトランザクションで包まれているか
- `app/services/matching/engine.rb` は実装済み・検証済み。issue が明示的に指示しない限り触らない

## 4. タイムゾーンと期間境界の扱い

締切はすべて JST、DB は UTC。フェーズも権限もここから導出されるので、
1時間や9時間のずれがそのまま操作の可否のずれになる。

```
rg -n 'Time\.(now|parse|at)|Date\.(today|parse)|DateTime|strftime|\.to_date' app/ lib/ --glob '!**/*_spec.rb'
```

確認すること。

- タイムゾーンを持たない値が混ざっていないか。`Time.now` `Date.today` は
  rubocop が弾くが、`Time.parse` や `String#to_time` は素通りする
- 文字列から日時を作る箇所が JST として解釈しているか。フォームからの入力が該当する
- **期間の境界。開始時刻を含み、終了時刻を含まない。** 締切ちょうどはその期間の外。
  `<` と `<=` の取り違えを目で確かめる
- 日付だけで比較していないか。`to_date` で丸めると JST/UTC の境界で1日ずれる
- 時刻で結果が変わるメソッドが、基準時刻をキーワード引数で受け取っているか。
  既定は `Time.current`。境界ちょうどを spec で突けない形になっていないか
- DB のデフォルト値やマイグレーションで `now()` を使っていないか。
  DB のタイムゾーン設定に依存してしまう
- ビューの残り時間表示が、サーバー側で計算した値を使っているか。
  クライアントの時計に依存していないか

## 報告

4項目それぞれについて、確認した結果を述べる。

- 問題を見つけたら、ファイルと行、なぜ不変条件に反するのか、どう直すかを示す
- 差分に該当箇所が無かった項目は「該当なし」と明示する。黙って飛ばさない
- 判断がつかないもの、grep では追い切れなかったものは、その旨をはっきり言う。
  確認できていないことを確認済みとして報告しない
