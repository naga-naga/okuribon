# 0007 交換会ページの本の一覧と希望リストでビジュアルガイドから採らなかったもの

- 日付：2026-08-21（この記録に集めた日。各項目を決めたのは #91 / #95 / #127 〜 #129 / #139 / #151 / #154 の時点）
- 発端：#182（元は `docs/spec.md` 10.2「ガイドから採らなかったもの」）

## 決めたこと

交換会ページの本の一覧と希望リスト編集（6.2、ガイドの `本の一覧 v2（統合）.dc.html` と
`モバイル版.dc.html`）について、資料の描き方を以下の23点で採らない。
同じ画面の上半分（状態ヘッダー）は 0006。

## 項目

### 本の一覧の「残り◯冊を表示」

**決めたこと** — カードを畳まず全件並べる

**なぜ** — 数人から十数人の交換会なので（10.）、畳んで隠すほどの数にならない

**却下した代替案** — 旧 `本の一覧.dc.html` も v2 もカードを途中で切って続きを畳む

### 本のカードの「コード登録済み」の印

**決めたこと** — 置かない

**なぜ** — ギフトコードは必須なので、どの本にも必ず付く。
常に真の印は、読む側にとって何の区別にもならない

**却下した代替案** — 資料はカードにこの印を置く

### 登録者名の丸いアバター

**決めたこと** — 並べるのは名前だけにする

**なぜ** — Google から `avatar_url` は受け取っているが、一覧で顔を見分ける用がない

**却下した代替案** — 資料は名前の前にアバターを置く

### カードを横に並べること

**決めたこと** — 5フェーズとも縦1列に積む（6.2）。
幅は希望リストが脇に並ぶ間と同じ 768px で止める

**なぜ** — 横に並べると、1枚開いたときに以降のカードがマスの中で総入れ替えになる。
1列のまま全幅へ広げると1行が80字を回る

**却下した代替案** — 資料は登録期間を3カラム、希望提出期間を2カラムのグリッドに並べる。
ただし資料は**閉じたカードしか描いていない**ので、開いた1枚をグリッドの中で
どう置くかについては、そもそも参照できるものが無い

### 展開したカードの置き場所

**決めたこと** — その場で下へ伸ばす

**なぜ** — 読み終わったら元の位置がそのまま残っている

**却下した代替案** — 旧 `本の一覧.dc.html` はグリッドの外（上部）に展開したカードを
1枚置く。v2 に対応する絵は無い（上の「カードを横に並べること」）

### 閉じたカードの見出しとストアへのリンク

**決めたこと** — どちらも閉じている間から出す（6.2）。
ストアへのリンクの置き場所は題の右にする

**なぜ** — 開いて初めて現れるものがあると、同じカードが開閉で別の顔になり、
読み比べていた1枚を見つけ直すことになる。下段に置かないのは、
開く口が出ないカードでは下段の中身が変わるため（6.2）

**却下した代替案** — 資料の閉じたカードは、おすすめポイントを見出しの無い本文だけで置き、
ストアへのリンクは開いた側の下段（「続きを読む」の隣）にしか持たない。
資料は開いた状態を描いていないので、2つの状態がどれだけ違ってよいかについては、
参照できるものが無い

### どのカードにも出る「続きを読む」

**決めたこと** — 折って隠れている本文があるカードにだけ出す（6.2）

**なぜ** — 資料の本文はどれも「——」で切れた長さに揃えてあり、
折られていないカードが混ざる画面は描かれていない

**却下した代替案** — 資料はすべてのカードの下段にこの口を描く

### 展開したカードの脇の案内文

**決めたこと** — 置かない

**なぜ** — 見出しの一文と同じ内容にあたる

**却下した代替案** — 資料は「希望の提出は◯日から」を開いたカードにも書く

### 一覧の一文の日時表記

**決めたこと** — 日時で書く

**なぜ** — 理由は招待URL着地画面の日程と同じ（0004）

**却下した代替案** — 資料は「希望の提出は2月15日から」と日付だけで書く

### モバイルの希望リストのシートの3段目

**決めたこと** — 畳む／開くの2段のままにする

**なぜ** — 3段目を分ける理由は「背後のスクロールを止めて長押しドラッグを安全にする」
ことにあり、ハンドルに `touch-action: none` を置けばその取り合いは起きない。
ハンドルはキーボードからも動かせるので、ドラッグ無しでも並べ替えられる。
段を増やすと、同じリストを映す場所が3つになる

**却下した代替案** — 資料は畳む／半分／全開の3段階を描き、
全開を並べ替え専用の全画面モードに充てる

### モバイルの希望リストの ↑↓

**決めたこと** — 狭い画面の行に ↑↓ を置かない（6.2）。
キーボードと読み上げに渡る道はハンドル自身に持たせる

**なぜ** — 資料が ↑↓ をモバイルの主としたのはドラッグとスクロールの取り合いの
ためだが、ハンドルに `touch-action: none` を置けばその取り合いは起きない。
実装は外す口を足したぶん題が6文字で切れたため、↑↓ のボタンを落とした。
以前は逆に、広い画面にも ↑↓ を出すことを「ハンドルはキーボードから届かない」を
理由に採っていた

**却下した代替案** — 資料（`モバイル版.dc.html` の A2）は狭い画面の行に
順位・題・↑↓ を並べる。並べ替えの口を1つに絞る点は、⠿ だけを描く広い画面の資料と
揃う（口の置き場所は次の「希望リストの ⠿」）。**資料の行は外す口を持たないので
（下の「希望リストの行の外す口」）、口が4つ並んだときに題へ何px残るかは
描かれていない**

### 希望リストの ⠿

**決めたこと** — つまむ口を順位そのものにし、⠿ を行から落とした（6.2）。
つまめることは、⠿ の形の代わりに輪郭で言う

**なぜ** — **資料の行は外す口を持たないので、⠿ と × が隣り合ったときに
何が起きるかは描かれていない。** 実装では44pxの的が4pxの隙間で並び、
並べ替えようとして希望から外す取り違えが起こりうる。
順位へ移すと、押すものが行の両端に離れる

**却下した代替案** — 資料は行の順位を素の文字で描き、つまむ口を別に置く。
`モバイル版.dc.html` の A2 / A3 は44pxの ⠿ を、`本の一覧 v2（統合）.dc.html` の
希望提出期間は行の右端に `cursor: grab` の ⠿ を持つ

### ドラッグ中の描き分け

**決めたこと** — 朱の破線と朱の輪郭のハンドル、それに淡い朱の面までを採る（6.2）

**なぜ** — ハンドルが順位になったので、朱にするのは字ではなく輪郭にあたる。
行そのものを落とす前から差し込んで順位も振り直すので、行き先は順位ごと見えている。
**線と文言を重ねると、同じことを3通りで言うことになる。** 影は使わない（10.1）

**却下した代替案** — 資料（`モバイル版.dc.html` の A3）は、動かしている行を
朱の破線・朱のハンドル・影で描いたうえ、差し込み位置に朱の線を引き、
順位の代わりに「◯位に移動中」と書き、その行から ↑↓ を落とす。
**行から ↑↓ を落とす描き方は、行が ↑↓ を持たなくなったので当たらない
（上の「モバイルの希望リストの ↑↓」）。** つまんだ瞬間に行の中身を
入れ替えないことのほうは、残る外す口に引き続き効く

**参照できるもの** — **つまんだ行がポインタに追従するかどうかは、資料が静止画なので
描かれていない。** 追従は採否ではなく補いにあたる（6.2）

### 結果公開後のカードの「コードを見る」

**決めたこと** — 一覧には置かない。取り出し口は 6.5 の1か所に限る（6.3 / 8.）

**なぜ** — 見出しの右端に結果画面への口があるので、行き先そのものは失われない

**却下した代替案** — 資料は成立したカードの下段にコードを開く口を置く

### 返却されたカードの副文

**決めたこと** — どちらも置かない

**なぜ** — 前者はこの画面からコードへ行けないので果たせず、
後者は返却の理由にあたる（6.2）。両方とも 6.5 が書く

**却下した代替案** — 資料は自分の本に「ギフトコードはそのまま使えます」、
他人の本に「希望した人がいませんでした」と添える

### 希望提出期間の絞り込みの区画

**決めたこと** — 「すべて ／ 自分の本」のまま通す

**なぜ** — 同じ位置のボタンがフェーズをまたいで別物になると、
押す前に読み直すことになる。取得枠は登録した冊数で決まるので、
「自分の本」は希望提出期間中も数える対象として要る

**却下した代替案** — 資料は「すべて ／ 未選択 ／ 希望に入れた」の3区画に差し替える

### 希望リスト末尾の「4位以下はここに追加されます」

**決めたこと** — 1冊も選んでいないときだけ出す

**なぜ** — 足す口はカードの側にしか無いので、末尾に枠を置いても押せない。
空のときに限り、どこから足すのかを書く

**却下した代替案** — 資料はリストの末尾に点線の枠を置く

### 希望リストの行の外す口

**決めたこと** — 行の右端に × を足す（6.2）。狭い画面は44px、広い画面は32pxの
四角にし、並べ替えの口の右に置く。文字は生成りに落とす

**なぜ** — 資料が外す口をカードの側にしか描かないのは、リストを今の並びを映すものとして
扱っているためで、その分け方は外すときだけ成り立たない。リストの中で押してほしいのは
並べ替えのほうなので、濃い字で置くと、消す口のほうが先に目に入る。
↑↓ を落としたあとはハンドルと同じ濃さで並ぶが、輪郭を持つのは外す口だけなので
取り違えない

**参照できるもの** — 資料の行は、広い画面が順位・題・ハンドル、狭い画面
（`モバイル版.dc.html` の A2）が順位・題・↑↓ で、どちらも外す口を持たない。
**外す口を持つ行そのものを資料が描いていないので、大きさと置き場所については
参照できるものが無い。** 採否ではなく補いにあたる

### 畳んだシートの冊数の行の位置

**決めたこと** — 畳んだシートの中身の1行目に置く

**なぜ** — ハンドルの行は開閉の状態を持つ外枠にあり、差し替えの外なので、
そこへ冊数を置くと1冊出し入れした直後だけ古い数が残る

**却下した代替案** — 資料はハンドルの行に
「希望リスト 3冊 ／ 枠2冊／あと1冊推奨」を並べる

### 準備中のカードの入る場所を象った空の枠

**決めたこと** — 登録期間で0冊のときと同じ1枚の面にし、文だけを差し替える（6.2）

**なぜ** — 空だと分かれば足りる用に対して、同じ状態が2通りの姿を持つことになるため。
2枚目以降の枠は形をなぞるだけで、読むものを持たない

**却下した代替案** — v2 の 00 はグリッドに破線の枠を3つ並べ、1枚目に
「登録された本は、おすすめポイントつきでここに並びます」と書く

### 実行待ちの「希望には入れていません」と「行き先は結果公開で分かります」

**決めたこと** — 下段そのものを持たせない（6.2）。
カードに出すのは「希望に入れた ◯位」だけとする

**なぜ** — 順位が出ている本が同じ画面に並んでいるので、出ていないことがそのまま
入れなかったことにあたり、入れなかった側にも書くと十数枚のうち大半が否定の文を持つ。
自分の本の一文のほうは、状態ヘッダーの「主催者がマッチングを実行すると結果が
公開されます」と同じことを1画面で2度言うことになる

**却下した代替案** — v2 の 03b は希望に入れなかった本と自分の本のカードにも
下段を置いて一文を書く

### 実行待ちの見出しの右の「希望の変更はできません」

**決めたこと** — 置かない

**なぜ** — 見出しはカードの並びの説明だけを持つ決めごとがあり（6.2）、
変更できないことは希望リストの見出しの脇の「確定済み」と、
カードから出し入れの口が消えていることで出ている

**却下した代替案** — v2 は「みんなの本 12冊」の右にこの一文を置く

### グリッド末尾の「もう1冊 登録する」のカード

**決めたこと** — 置かない。登録の口は状態ヘッダーの「あなたがすること」の直下に
1つだけにする（6.1）

**なぜ** — 同じ行き先を指すものが上と下にあると、統合で消したはずの
「主と副で2つ並ぶ導線」が形を変えて戻る。一覧の末尾は、全件を読み終えた位置であって、
次の1冊を書きに行く位置ではない

**却下した代替案** — v2 の 01 はカードの並びの最後に点線の枠を置いて
登録の口をもう1つ作る
