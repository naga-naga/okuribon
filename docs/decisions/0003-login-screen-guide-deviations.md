# 0003 ログイン画面でビジュアルガイドから採らなかったもの

- 日付：2026-08-21（この記録に集めた日。各項目を決めたのは #12 / #81 / #91 の時点）
- 発端：#182（元は `docs/spec.md` 10.2「ガイドから採らなかったもの」）

## 決めたこと

ログイン画面（ガイドの `ログイン・招待・交換会一覧.dc.html` の 01）について、
資料の描き方を以下の3点で採らない。

## 項目

### ログイン画面のプロバイダ

**決めたこと** — Google のみとする（11.）

**なぜ** — 顔見知りの少人数グループで使うため、ログインできない人が1人でも出る
プロバイダは選べない。想定している利用者が確実に持っているアカウントが Google だから

**却下した代替案** — 資料はプロバイダを3つ並べる。招待URL着地画面の参加ボタンの
横にある「Google / GitHub / Discord」も同じ理由で採らない（0004）

### ログイン画面をログイン済みで開いたとき

**決めたこと** — 交換会一覧へ送る。ログイン画面そのものには共通ヘッダーを出さない

**なぜ** — 以前は開けるようにしていたが、それはログアウトの口がその画面にしか
なく、追い返すと抜けられなくなるためだった。共通ヘッダーが全画面でログアウトを
持つので（#81）、その理由ごと畳んだ。共通ヘッダーを出さないのは、この画面が
サービス名を見出しに大きく出すためで、ヘッダーにも出すと同じ名が上下に並ぶ

**却下した代替案** — 資料の「01 ログイン」も帯を持たないので、
ヘッダーを出さない点については資料と揃う

### 開発用ログイン画面（`/dev/login`）

**決めたこと** — 既存のトークンだけで素朴に組む。10.2 の対応表には載せない。
ログイン画面の末尾にこの画面へのリンクを置く

**なぜ** — 利用者の目に触れない開発用の道具にあたる。リンクもガイドには無い要素だが、
開発とテストの環境にしか出ない。URL を直に打たせると、利用者を入れ替えるたびに打つことになる

**参照できるもの** — 対応する画面がガイドに無い

## 影響する場所

- `app/views/sessions/new.html.erb`
- `app/views/dev/sessions/new.html.erb`
