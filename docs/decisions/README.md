# 判断の記録

「いつ・何を・なぜ決めたか」を1件1ファイルで積む。規範は `docs/spec.md` が持ち、
ここには決めた経緯と却下した代替案を置く。守るべきことをここにだけ書かない。
記録を読まないと実装の可否が分からない状態になったら、その決まりは spec.md へ移す。

記録は書き換えない。決めた内容が変わったら新しい記録を足し、
古い記録の冒頭に新しい番号への参照を添える。いつ何を考えていたかが残ることに
この置き場の意味があるため。

## spec.md に残すもの、ここへ移すもの

どちらに書くかは「いま画面にあるものだけで読めるか」で分ける。

`docs/spec.md` に残すもの。

- 決まりそのものと、決まりの形を決めている制約。ブラウザや Rails の挙動、
  実際に測った数値など、次に触る人がその場で要るもの
- 判断が乗っている前提と、それが崩れる条件
- 別案を1文で退けている理由。「◯◯は持たない／置かない」のように、決まりそのものが
  案の否定になっているものを含む。案を並べて比べているものは、段落ごと移す

ここへ移すもの。

- 過去の実装との比較（「以前は」「統合前は」「一度は」）。いま画面に無いものを
  引き合いに出す文は、現在の実装だけを読む人には当たらない
- 検討して採らなかった案。案を挙げて比べている段落ごと移す
- どの issue で決まったかの出典。日付と発端としてこちらが持つ

移したら、spec.md の側は決まりを守るのに要る一文を残したうえで
`decisions/NNNN` を添える。理由を丸ごと抜いて番号だけにしない。
なぜそうなのかを読むたびに記録を開くことになる。

## ファイル名

`NNNN-英小文字ケバブの要約.md`。番号は4桁の連番。コードやドキュメントから
`decisions/NNNN` の形で参照するため、振り直さない。

## 書式

```markdown
# NNNN 決めたことの要約（終止形）

- 日付：YYYY-MM-DD
- 発端：issue / PR の番号

## 決めたこと

## なぜ

## 却下した代替案

案ごとに、なぜ採らなかったかを書く。

## 影響する場所

この判断に乗っているコード・文書・skill。無ければ節ごと省く。
```

1決定1ファイルを基本とする。**ビジュアルガイドの採否だけは画面ごとに1ファイルへまとめ、
1項目を `###` の見出し1つとして積む**（0002〜0011）。採否は1画面あたり十数件あり、
1件1ファイルにすると番号から中身を辿れなくなる。引くのは「この画面を触るとき」なので、
画面で束ねたほうが行き着ける。積み先の一覧は `docs/spec.md` 10.2 にある。

この束だけは、新しい採否をその画面のファイルへ項目として足してよい。
書き換えないという上の決まりが当たるのは既にある項目の判断が変わったときで、
そのときは新しい記録を立て、当該項目の見出しの直下から参照する。

採否の項目は次の3つで書く。

- **決めたこと** — 実装がどうするか
- **なぜ** — そう決めた理由
- **却下した代替案** — 資料がどう描いているか

資料に対応する絵が無いものは、採否ではなく補いにあたる。
却下した代替案の代わりに **参照できるもの** を置き、何が描かれていなかったかを書く。
