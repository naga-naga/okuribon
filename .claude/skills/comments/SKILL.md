# コメントの見直し

書いた直後のコメントは、どれも書いた理由があるように見える。落とすべきものが残るのは
基準を知らないからではなく、**足したコメントを数え上げないまま次へ進むから**である。
ここでやることは、1件残らず並べて、1件ずつ当てることに尽きる。

基準そのものは `CLAUDE.md`「コメント」が持つ。**先にそれを開く。**
この手順書は分類を書き写さない。写しは元を直したときに古くなる。

## 1. 差分に足したコメントを数え上げる

```
git diff main...HEAD    # ブランチ全体
git diff                # 未コミットの変更
```

追加・変更された行のうち、コメントにあたるものをすべて拾う。取りこぼしを防ぐため、
差分を目で追ったあとに機械でも当てる。

```
git diff main...HEAD -U0 | rg '^\+' | rg '#|//|/\*|<%#'
```

対象は Ruby・ERB・JavaScript・YAML・Markdown 中のコード片。
コミットメッセージと PR 本文は別の決まりなので、ここでは見ない。

**拾った数を先に言う。** 「3件見た」と数えてから当てると、残りを飛ばしにくい。

## 2. 1件ずつ当てる

各コメントについて、順に問う。1つでも当たれば落とす。

- **消したとき、コードから読み取れなくなるものがあるか。** 無ければ落とす。
  名前や式の言い換え、クラス冒頭の要約、spec の `it` の言い換えがここに当たる
- **固有名詞を入れ替えるだけで、他の箇所でも通用する文か。** それは設計方針であって、
  この箇所に固有の理由ではない。持ち場（`docs/spec.md` か `CLAUDE.md`「規約」）へ寄せる。
  **持ち場にまだ無い方針なら、落とす前に持ち場へ書き足す**
- **他所に同じことが書いてあるか。** `docs/spec.md`・`CLAUDE.md`・`docs/decisions/` を
  実際に引いて確かめる。あれば落とす。節番号や issue 番号への参照も落とす
- **同じことを2文で言っていないか。** 1文目が2文目の要約になっているなら1文目を落とす
- **`CLAUDE.md`「コメント > 言い回し」に当たる語が混じっていないか**

## 3. 置き場所を見る

残すと決めたコメントが、**それが説明しているコードの隣にあるか**を確かめる。
宣言のまとまりの上に置いたつもりで、実際には数行下の式の説明になっていることがある。
読む人は直下のコードの説明として読むので、指す先がずれていると外れた説明になる。

## 4. 報告する

落としたものと残したものを、それぞれ理由とともに述べる。

- 落としたものは、どの問いに当たったかを言う
- 残したものは、当たらなかった理由を言う。特に、他所と重なって見えるのに残したものは、
  何が違うのかをはっきり言う
- 持ち場へ書き足したものがあれば、どこへ何を足したかを言う

1件も落とすものが無かったときは「無かった」と言う。数え上げた件数を添える。
