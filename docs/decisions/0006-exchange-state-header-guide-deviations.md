# 0006 交換会ページの状態ヘッダーでビジュアルガイドから採らなかったもの

- 日付：2026-08-21（この記録に集めた日。各項目を決めたのは #126 / #139 / #140 / #141 の時点）
- 発端：#182（元は `docs/spec.md` 10.2「ガイドから採らなかったもの」）

## 決めたこと

交換会ページの状態ヘッダー（6.1、ガイドの `本の一覧 v2（統合）.dc.html`）について、
資料の描き方を以下の12点で採らない。同じ画面の下半分（本の一覧と希望リスト）は 0007。

通知（7.）に触れる項目は、#43 が未実装だった時点の判断にあたる。
#43 は完了したので前提は変わっている。採否を見直すなら新しい記録を立てる。

## 項目

### 交換会ページの上部の帯

**決めたこと** — 共通ヘッダーを現行のまま通す（左がパンくず、右がアカウント）。
交換会名・主催者名・参加人数は本文側の状態ヘッダーが持つ

**なぜ** — 共通ヘッダーの中身を画面ごとに変えない決めごと（0002）を、
この画面のためだけに崩さないため

**却下した代替案** — v2 は帯の左に「← 交換会一覧 ／ 交換会名 ／ 主催 ／ 人数」、
右にアバターを並べる

### 交換会ページのモバイル

**決めたこと** — 狭い画面での状態ヘッダーの畳み方と、畳んだ帯と希望リストのシートの
すみ分けは 6.1 / 6.2 に書いたとおりに補う

**参照できるもの** — v2 は 1180px の絵しか持たず、`モバイル版.dc.html` は統合前の
2画面を描いている。参照できるものが無かったので、採否ではなく補いにあたる

### 狭い画面の畳んだ帯

**決めたこと** — 375px では4つとも1行に入らないため、交換会名を落とす（6.1）

**参照できるもの** — 資料に対応する絵が無い。畳んだ帯は
`本の一覧 v2（統合）.dc.html` の 03 が 1180px で1枚描くだけで、
`モバイル版.dc.html` は統合より前のものなので帯を持たない。
参照できるものが無かったので、採否ではなく補いにあたる

### 交換会ページの締切の3段階のエスカレーション

**決めたこと** — 朱の文字1つで通す。「あなたがすること」が朱のときは、
締切のほうを墨に落とす

**なぜ** — 朱を1画面に1箇所だけにする決めごと（10.1）があり、この画面では
「あなたがすること」が状態に応じて朱の面を持つ。締切も面を持つと、朱が2つ並んで、
どちらに急かされているのか読めなくなる。統合後はさらに、下半分に「希望に追加」が
十数個並ぶので、上半分の朱は1つに絞る理由が増えている

**却下した代替案** — 旧 `交換会トップ.dc.html` は残り時間で薄墨・朱の文字・朱の面と
切り替える

### 「概要と日程」を畳んで格納すること

**決めたこと** — 畳まず状態ヘッダーの下に出したままにする（6.1）

**なぜ** — 畳んだ枠も1行ぶんの面を取るので節約できる高さが少なく、
「本を登録する」を押す直前に1クリック挟むほうが重い。そもそも実装は資料の
上部の帯を採らないので（上の「交換会ページの上部の帯」）、口を置く場所も無い

**却下した代替案** — v2 は上部の帯の右に「概要と日程」の口を置き、中身を格納する。
準備中だけ本文の右側に常設するという v2 の 00 の描き分けも、
全フェーズで出したままになるので採らない

### 準備中の右の脇（概要 / 日程 / 参加している人）

**決めたこと** — 置かない。概要と日程は全フェーズで状態ヘッダーの外に
全幅で常設する（6.1）

**なぜ** — 準備中だけ脇へ移すと、フェーズが変わった瞬間に同じものが画面の
別の場所へ動く。参加者のアバターは招待URL着地画面と同じ理由で採らない（0004）。
顔ぶれは主催者管理の参加者一覧が持つ（6.8）

**却下した代替案** — v2 の 00 は本文の右に 340px の脇を作り、
概要・日程・参加者のアバターを縦に積む

### 結果公開の状況の数字

**決めたこと** — 他のフェーズと同じ3つの枠に「本 ／ 成立 ／ 返却」として入れる

**なぜ** — 枠の位置は動かさず中身だけを入れ替える決めごと（6.1）に合わせるため。
1行に畳むと、結果公開だけ数字の並ぶ場所が変わる

**却下した代替案** — v2 の 04 は「成立 10冊・返却 2冊」を1行にして
結果ボタンの横に置く

### 状態ヘッダーの「自分の本を見る（◯冊）」

**決めたこと** — 置かない

**なぜ** — 行き先は見出しの右にある絞り込み（「すべて ／ 自分の本 ◯」）と同じで、
自分の冊数もそちらが出している。取得枠として読むための冊数は状況の数字が別に持つ

**却下した代替案** — v2 の 01 は登録ボタンの隣にこの口を並べる

### 交換会ページの主催者管理への導線

**決めたこと** — 状態ヘッダーの1行目の右端に、主催者にだけ出す（6.1 / 6.8）

**参照できるもの** — v2 に対応する絵が無い。帯の右はどのフェーズもアバターで、
主催者として開いた姿を描いていない。参照できるものが無かったので、
採否ではなく補いにあたる

### 実行待ちの主催者の交換会ページ

**決めたこと** — 主催者の面だけは 6.1 の既存の型から起こし、
「あなたがすること」の直下に操作を1つ置いた。位置も大きさも登録期間の
「本を登録する」と同じにする

**参照できるもの** — 資料に対応する絵が無い。`本の一覧 v2（統合）.dc.html` の 03b は
待つ側だけを描いており、主催者が同じ画面を開いた絵を持たない。
参照できるものが無かったので、採否ではなく補いにあたる

### 実行待ちの「みずき さんの実行を待っています」の帯

**決めたこと** — 置かない

**なぜ** — 同じことを `Exchanges::Todo` の detail が既に書いており
（「主催者がマッチングを実行すると結果が公開されます」）、帯を足すと
同じ一文が上下に並ぶ。主催者を名指ししないのは、待たせている当人を
参加者全員の画面で名指しする形になるため

**却下した代替案** — v2 の 03b は「あなたがすること」の下に
主催者を名指しした帯を1つ置く

### 準備中の「始まったらDiscordに投稿されます」と、実行待ちの「結果はDiscordにも投稿されます」

**決めたこと** — 置かない。ほかの画面の Discord の一文と同じ扱いにする

**なぜ** — 通知は 7. の担当なので（#43）、いま書いても果たせない

**却下した代替案** — v2 の 00 と 03b はカードの外にこの一文を添える
